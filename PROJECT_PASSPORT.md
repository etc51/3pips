## 1. Короткая суть проекта

Проект проверяет короткосрочную идею торговли фьючерсами MOEX и NEO/perp через поток данных T-Bank API.

Базовая торговая идея:

- искать краткосрочный импульс цены;
- входить только если цена, моментум, VWAP, локальный пробой, объем и стакан согласованы;
- сразу иметь защитный стоп;
- при движении в плюс включать трейлинг;
- считать результат в рублях с учетом комиссии;
- в paper-режиме копить фактическую статистику по каждому тикеру, семейству и профилю;
- автоматически уменьшать риск или ставить паузу, если редкие большие стопы начинают убивать серию маленьких плюсов.

Главная текущая проблема, которую проект решает: не дать ситуации `20 мелких прибыльных сделок + 4 больших стопа = весь плюс уничтожен`.

## 3. Важное ограничение

Сейчас это paper-система. Она:

- получает поток цен, стакана, сделок и свечей через T-Bank API;
- симулирует входы и выходы;
- считает PnL, комиссии, стопы, риск;
- ведет журналы;
- не отправляет реальные торговые заявки.

Если проект переводить в live, нужно отдельно реализовать слой реальных заявок, сверку с брокером, контроль частичных исполнений, отмену/перестановку stop-limit и аварийное закрытие.

Профили были получены через несколько внешних расчетов в ChatGPT:

- сначала широкие поиски по многим фьючерсам;

- главная задача текущей фазы - live-paper статистика по реальному потоку.

## 6. Внутренние режимы внутри каждого портфеля

Фьючерсные внешние портфели запускают два внутренних контура:

### `strict`

Более жесткий вход:

- `lookback = 6`
- `vol_mult = 1.15`
- `vwap_buffer = 1 tick`
- `trend_need = 1.0 tick`
- `signal_need = 2 ticks`
- `book_imbalance = 1.35`
- `max_fee_to_stop = 0.40`

### `aggressive`

Более мягкий вход:

- `lookback = 4`
- `vol_mult = 0.7`
- `vwap_buffer = 0`
- `trend_need = 0.5 tick`
- `signal_need = 1 tick`
- `book_imbalance = 1.2`
- `max_fee_to_stop = 0.55`

Оба режима используют один и тот же профиль тикера, но с разными фильтрами входа.

`stock_watch` работает одним внутренним режимом `aggressive`, потому что его параметры входа берутся напрямую из stock-research JSON: `lookback`, `threshold`, `trend_fast/slow`, `volume_multiplier`, `session_filter`, `stop/trail/activation`.

## 7. Профиль тикера

Каждая строка профиля содержит:

- `ticker` - контракт;
- `quality` - внешний контур/статус;
- `stop_ticks` - полный стоп в тиках;
- `trail_ticks` - расстояние трейлинга;
- `trail_arm_ticks` - с какого движения в плюс включается трейлинг;
- `target_min_ticks` - минимальное движение до условной цели;
- `max_attempts` - лимит попыток;
- `tick_rub` - стоимость тика;
- `risk_1lot_rub` - риск одного контракта по стопу;
- `v7_family` - семейство;
- `v7_signal_family` - семейство сигнала из research;
- `v7_direction` - разрешенное направление: `long`, `short`, `both`;
- `v7_entry_timing` - модель входа из research;
- `v7_test_net_2t`, `v7_test_pf_2t` - тестовые метрики из расчетов.

В текущем live-paper боте фактический сигнал считается встроенной online-логикой. Поля `v7_signal_family` и `v7_entry_timing` используются как описание происхождения профиля, а не как отдельный исполняемый движок сигналов.

## 8. Определение семейства

Функция семейства:

- для обычных фьючерсов убирается последний годовой символ и месяц;
- например `BRQ6`, `BRU6`, `BRV6` -> `BR`;
- `BMM6`, `BMN6` -> `BM`;
- `PTM6`, `PTZ6` -> `PT`;
- `perpA` оставляется как отдельный актив, например `AMDperpA`.

Семейство используется для:

- анализа плюса/минуса;
- запрета дублей около ролловера;
- Risk Governor;
- авто-переноса на следующий контракт;
- защиты дневной прибыли.

## 9. Источники данных

Бот работает через T-Bank API SDK `t_tech.invest`.

Используется:

- поиск фьючерса по тикеру;
- получение спецификации инструмента;
- получение `figi` и `uid`;
- `min_price_increment` как размер тика;
- `min_price_increment_amount` как стоимость тика;
- `initial_margin_on_buy`, `initial_margin_on_sell` как ГО;
- `expiration_date`;
- seed 1-minute candles за последние `240` минут;
- market data stream:
  - last price;
  - trades;
  - order book;
  - candles;
- polling fallback, если stream стал старым.

Параметры потока:

- `orderbook_depth = 10`
- `snapshot_sec = 10`
- `stream_stale_sec = 15`
- `fallback_poll_sec = 2`

Если поток молчит более `15` секунд, включается polling-страховка. Когда поток оживает, бот снова ориентируется на stream.

## 10. Комиссия

Для paper-расчетов используется модель:

`side_fee = commission_side_rub(spec, 1, 0.00025, None)`

Итого круговая комиссия:

`round_turn_fee = 2 * side_fee * qty`

В PnL:

`gross = ticks * tick_rub * qty`

`net = gross - 2 * side_fee * qty`

Комиссия включается:

- в закрытую сделку;
- в полный стоп-риск;
- в фильтр `fee_filter`;
- в включение трейлинга, потому что трейлинг не должен подтягивать стоп в формально безубыточную, но комиссионно убыточную зону.

## 11. Startup-фильтр комиссии

На старте контракта:

`round_fee_ticks = 2 * side_fee / tick_rub`

Если:

`round_fee_ticks > stop_ticks * 0.55`

контракт не загружается.

Это грубый стартовый фильтр, чтобы не торговать профили, где комиссия слишком велика относительно стопа.

Внутри `strict` используется еще жестче:

`fee_ticks <= stop_ticks * 0.40`

Внутри `aggressive`:

`fee_ticks <= stop_ticks * 0.55`

## 12. BR small-stop policy

Для BR-профилей с маленьким стопом есть отдельная политика.

Константы:

- `BR_POLICY_MIN_STOP_TICKS = 15`
- `BR_POLICY_MAX_SPREAD_TO_STOP = 0.40`
- `BR_POLICY_LOSS_PAUSE_COUNT = 3`
- `BR_POLICY_LOSS_PAUSE_SECONDS = 2 часа`

Если профиль BR подпадает под small-stop policy:

- стоп не может быть меньше `15` тиков;
- вход блокируется, если спред больше `40%` от стопа;
- после серии из `3` стопов по BR-small-stop группе ставится пауза на `2` часа.

Причина: BR может быть прибыльным, но при малом стопе широкий спред и серии стопов быстро ломают математику.

## 13. Расчет сигнала

Сигнал считается по последним 1-minute candles и стакану.

Минимум данных:

- нужно минимум `12` свечей;
- иначе `warmup`.

Вычисляемые признаки:

- `last_close` - close последней свечи;
- `prev_close` - close предыдущей свечи;
- `last_vol` - объем последней свечи;
- `avgv` - средний положительный volume за последние 20 свечей до текущей;
- `vwap` - volume VWAP по накопленным свечам;
- `mom = (last_close - prev_close) / tick`;
- `fast = среднее close последних 2 свечей`;
- `slow = среднее close последних 5 свечей`;
- `trend = (fast - slow) / tick`;
- `high = максимум high на lookback`;
- `low = минимум low на lookback`;
- `bid_qty`, `ask_qty` - сумма объемов первых 3 уровней стакана.

Фильтры перед сигналом:

1. Стакан не должен быть пустым:

`bid_qty > 0` и `ask_qty > 0`

2. Для BR-small-stop:

`spread_ticks <= stop_ticks * 0.40`

3. Комиссия:

`fee_ticks <= stop_ticks * max_fee_to_stop`

4. Движение последних 5 свечей:

`max(high - low over last 5 candles) / tick >= fee_ticks + 2`

5. Объем:

`last_vol >= avgv * vol_mult`

6. Дисбаланс стакана:

Для long:

`bid_qty >= ask_qty * book_imbalance`

Для short:

`ask_qty >= bid_qty * book_imbalance`

## 14. Условие long

Long-сигнал:

`last_price >= vwap + vwap_buffer * tick`

и

`trend >= trend_need`

и

`mom >= signal_need`

и

`last_close >= high`

и

`vol_ok`

и

`long_book`

Если профиль разрешает только `short`, long-сигнал будет отфильтрован `direction_filter`.

## 15. Условие short

Short-сигнал:

`last_price <= vwap - vwap_buffer * tick`

и

`trend <= -trend_need`

и

`mom <= -signal_need`

и

`last_close <= low`

и

`vol_ok`

и

`short_book`

Если профиль разрешает только `long`, short-сигнал будет отфильтрован `direction_filter`.

## 16. Порядок проверки перед входом

Перед открытием позиции бот проходит цепочку:

1. Есть ли активная shadow-модель выхода. Если есть, сначала ведем ее до закрытия.
2. Торговля разрешена по времени.
3. Нет force-close режима.
4. `attempts < max_attempts`.
5. Нет cooldown после закрытия.
6. Не было уже входа на этой же свече.
7. Нет уже открытой позиции по этому тикеру в любом контуре.
8. Нет roll-family конфликта.
9. Контракт не слишком близко к экспирации.
10. Есть сигнал.
11. Сигнал совпадает с разрешенным направлением профиля.
12. Есть исполнимая цена в стакане.
13. Risk Governor разрешает вход и назначает лимит стоп-риска.
14. Sizing считает количество контрактов.
15. Если qty >= 1, открывается paper-позиция.

## 17. Цена входа

Для входа:

- long входит по `ask`;
- short входит по `bid`.

Если нужной стороны стакана нет, вход блокируется:

`book_filter no_executable_entry`

Цена округляется к шагу цены.

## 18. Размер позиции

Размер считается через `paper_sizing`.

Ограничения:

1. По ГО:

`max_total_margin = equity * 0.80`

`per_position_limit = equity * 0.20`

`free_margin = max_total_margin - used_margin`

`budget = min(free_margin, per_position_limit)`

`margin_qty = floor(budget / margin_per_contract)`

2. По полному стопу:

`gross_stop_per_contract = stop_ticks * tick_rub`

`round_turn_fee_per_contract = 2 * side_fee`

`full_stop_per_contract = gross_stop_per_contract + round_turn_fee_per_contract`

`risk_qty = floor(max_full_stop_rub / full_stop_per_contract)`

3. Финальный размер:

`qty = min(margin_qty, risk_qty)`

Если Risk Governor дал режим:

- `normal`: `max_full_stop_rub = 4000`
- `reduced`: `max_full_stop_rub = 2000`
- `micro`: `max_full_stop_rub = 1000`
- `paused_today`: вход запрещен

Важно: риск ограничивается количеством контрактов, а не сужением стопа. Стоп остается тем, который дал профиль.

## 19. Открытие позиции

После входа создается `Position`:

- direction;
- entry_price;
- qty;
- best_price;
- stop_price;
- opened_at.

Стоп ставится на расстоянии `stop_ticks` от входа.

Также создаются shadow-модели:

- `stream_stoplimit`;
- `candle_like`.

Они нужны для сравнения двух моделей выхода:

- более жесткая stream/stop-limit;
- более мягкая свечная модель, которая сейчас является основной actual-моделью.

## 20. Текущая фактическая модель выхода

В запуске включено:

`--actual-exit-model candle_like`

Это значит:

- фактический paper-выход оценивается по закрытой 1-minute candle;
- стоп/трейлинг обновляется на закрытии свечи;
- это ближе к тому, как профили считались в GPT/backtest, чем жесткое дергание стопа на каждый тик.

При этом shadow-журнал продолжает сравнивать `stream_stoplimit` и `candle_like`.

## 21. Трейлинг

Для long:

`move_ticks = (trigger_price - entry_price) / tick`

Для short:

`move_ticks = (entry_price - trigger_price) / tick`

Трейлинг включается, если:

`move_ticks >= max(trail_arm_ticks, fee_ticks + 1)`

После включения:

- стоп подтягивается функцией `update_stop`;
- стоп не должен оставаться в зоне, где с учетом комиссии сделка будет отрицательной;
- минимальный стоп для нетто-плюса:

для long:

`entry_price + (fee_ticks + 0.5) * tick`

для short:

`entry_price - (fee_ticks + 0.5) * tick`

Идея: если трейлинг уже активирован, бот старается не фиксировать формальный безубыток, который после комиссии станет минусом.

## 22. Stop-limit / emergency модель

В `stream_stoplimit` модели:

1. Если цена не коснулась стопа, ничего не делаем.
2. Если стоп коснулся, смотрим доступный объем в стакане на стоп-цене или лучше.
3. Если объема достаточно:

`broker_stop_limit_fill`

4. Если объема не хватает, считаем проскок:

`overrun_ticks`

5. Если проскок >= `2` тика:

`emergency_market_after_missed_limit`

То есть логика такая: сначала считаем, что сработал stop-limit; если лимитка не исполнилась и цена ушла дальше, закрываем аварийно маркетом.

В текущем actual paper стоит `candle_like`, но `stream_stoplimit` пишется в shadow-журнал для сравнения.

## 24. Risk Governor

Файл состояния:

`reports/paper_runs/v7_live_20260525/<portfolio>_risk_policy_state.json`

Risk Governor - отдельный слой, который не меняет сигнал, но решает:

- можно ли входить;
- каким максимальным полным стопом в рублях;
- нужно ли уменьшить размер;
- нужно ли поставить семью на паузу до завтра.

Ключ статистики профиля:

`contour | family | secid | direction | stop_ticks | trail_ticks | trail_arm_ticks | source_profile`

Ключ статистики семьи:

`family`

Что копится:

- trades;
- wins;
- losses;
- net;
- gross;
- fees;
- gross_profit;
- gross_loss_abs;
- best_win;
- worst_loss;
- positive_nets;
- recent_nets.

## 25. Risk Governor: режимы

### `normal`

Полный стоп до `4000 ₽`.

### `reduced`

Полный стоп до `2000 ₽`.

### `micro`

Полный стоп до `1000 ₽`.

### `paused_today`

Новые входы по семье запрещены до следующего дня.

Открытые позиции задним числом не уменьшаются. Режим влияет на следующие входы.

## 26. Risk Governor: правила по хвостам

Новый контракт, если он получен автопереносом и источник профиля отличается от текущего контракта:

`micro`, пока не набрано `30` сделок.

Если профиль имеет минимум 2 сделки, минимум 2 убытка и net < 0:

`micro`

Если профиль имеет минимум 2 сделки и net <= `-0.5 * base_limit`:

`reduced`

Если семья имеет минимум 2 сделки, минимум 2 убытка и net <= `-base_limit`:

`micro`

Если семья имеет минимум 2 сделки и net <= `-0.5 * base_limit`:

`reduced`

Если:

`base_limit / median_win >= 10`

то `micro`.

Если:

`base_limit / median_win >= 7`

то `reduced`.

Если:

`profile_worst_loss_abs / profile_gross_profit >= 0.90`

то `micro`.

Если:

`profile_worst_loss_abs / profile_gross_profit >= 0.50`

то `reduced`.

Если:

`family_worst_loss_abs / family_gross_profit >= 0.90`

то `micro`.

Если:

`family_worst_loss_abs / family_gross_profit >= 0.55`

то `reduced`.

Если последние 3 сделки профиля отрицательные:

`micro`.

## 27. Risk Governor: защита дневной прибыли

Для каждого семейства отдельно ведется дневной net и дневной high.

Если семейство за день достигло:

`high >= 3000 ₽`

и потом отдало:

`drawdown >= max(1500 ₽, high * 0.35)`

то включается:

`paused_today`

Это защита от сценария:

`семейство накапало плюс, потом серия стопов съела день`.

## 28. Автоматический второй шанс

Семья не запрещается навсегда.

Если семья смешанная или контракт новый:

- новый контракт стартует в `micro`;
- собирает сделки;
- если хвостов нет и статистика улучшается, Risk Governor перестает находить причины для `micro/reduced`;
- режим автоматически возвращается к `normal`.

Никакого ручного снятия запрета не требуется, если статистика стала нормальной.

## 29. Экспирация и автоперенос

Параметры:

- `roll_observe_days = 10`
- `no_new_expiry_days = 5`
- `expiry_force_close_days = 3`

Правила:

1. Если до экспирации <= 5 дней, новые входы запрещаются.
2. Если до экспирации <= 3 дней, открытая позиция закрывается принудительно.
3. За 10 дней до экспирации бот ищет следующий контракт того же семейства.
4. Если для нового контракта есть свой профиль, используется он.
5. Если своего профиля нет, профиль клонируется со старого контракта.
6. Клонированный профиль попадает под Risk Governor как новый контракт и должен пройти `micro/probation`.

Для NEO/perp:

- если expiration year >= 2099 или family заканчивается на `perpA`, auto-roll пропускается;
- такие инструменты считаются perpetual/far-expiration.

## 30. NEO/perp правила

Для `neo` включены:

- `--no-new-after 19:00`
- `--force-close-at 23:50`

Смысл:

- после 19:00 MSK новые входы запрещены;
- до полуночи позиции принудительно закрываются;
- цель - не попадать на перенос/overnight-логику NEO.

## 31. Дубли и конфликты

Бот запрещает:

- открыть второй раз тот же тикер, если позиция уже есть;
- открыть другой контракт того же семейства в roll-window, если есть семейный roll-конфликт;
- открыть позицию на той же свече повторно;
- открыть позицию, если active shadow-модели еще не закрылись после предыдущей сделки.

## 32. Fallback при падении stream

Если stream не обновляется дольше `stream_stale_sec = 15`, включается polling:

- last prices;
- orderbook;
- обработка выходов;
- snapshot;
- health.

Polling работает каждые `2` секунды.

Когда stream снова живой, бот продолжает работать через stream.

## 36. Что означает широкий спред

В snapshot считается:

`spread_to_stop_ratio = spread_ticks / stop_ticks`

Классы:

- `SPREAD_OK`: нормально;
- `SPREAD_WATCH`: спред заметен;
- `SPREAD_HEAVY`: широкий;
- `SPREAD_DOMINATES`: спред доминирует над стопом;
- `NO_BOOK`: нет стакана.

Пример:

`COINperpA`, spread `14`, stop `34`, ratio `41.2%`.

Это значит, что спред равен 41.2% от стопа. Такой инструмент может иметь исторический edge, но в live-paper требует осторожного размера и наблюдения.

## 37. Что уже известно по статистике

По закрытым сделкам V7 до внедрения Risk Governor:

- часть семейств была прибыльной;
- часть семейств имела большие хвостовые стопы;
- проблема была не только в направлении, а в соотношении среднего плюса к полному стопу.

Примеры:

- `PT` выглядел наиболее чисто;
- `BR` прибыльный, но опасный из-за отдельных больших стопов;
- `BM`, `GL`, `BT`, `S1`, `Si` показывали хвостовой риск;
- `AMDperpA` выглядел неплохо, но NEO требует отдельной вечерней политики.

После внедрения Risk Governor:

- `BTM6/BTK6` автоматически ушли в `micro`;
- `BMM6/BMN6` ушли в `reduced`;
- спорные семьи не запрещены навсегда, но следующий вход получает меньший размер.

## 38. Текущие параметры риска

Базовые:

- capital per portfolio: `800000 ₽`
- max total margin: `80%`
- max position margin: `20%`
- normal full stop: `4000 ₽`
- reduced full stop: `2000 ₽`
- micro full stop: `1000 ₽`

Profit guard:

- min daily family high: `3000 ₽`
- drawdown pct: `35%`
- drawdown min: `1500 ₽`

Stop-to-median:

- reduced threshold: `7`
- micro threshold: `10`

Probation:

- new rolled contract: `30` trades before it can naturally escape probation if stats are healthy.

## 39. Главное, что нельзя ломать

1. Нельзя сужать стоп вместо уменьшения количества контрактов. Стоп - часть профиля.
2. Нельзя смешивать NEO/perp с классикой.
3. Нельзя считать открытый PnL как окончательный результат.
4. Нельзя переносить mixed-семейство на новый контракт сразу полным размером.
5. Нельзя отключать Risk Governor без отдельного решения.
6. Нельзя удалять open positions при рестарте; они должны восстанавливаться.
7. Нельзя менять actual exit model на stream/tick без отдельного сравнения, потому что текущие профили считались ближе к candle-like логике.
8. Нельзя оценивать стратегию только по win rate. Нужно смотреть средний плюс, медианный плюс, худший стоп, комиссии и PnL семьи.

## 40. Что нужно анализировать дальше

Основные вопросы:

1. Какие семейства дают устойчивый закрытый PnL после Risk Governor.
2. Какие семьи постоянно уходят в `micro` и не восстанавливаются.
3. Где средний плюс слишком мал относительно полного стопа.
4. Как отличаются shadow-модели `stream_stoplimit` и `candle_like`.
5. Какие тикеры дают прибыль только грязными, но проигрывают после комиссий.
6. Какие сессии лучше:
   - основная;
   - утренняя;
   - вечерняя.
7. Нужно ли добавить family-level daily take-profit stop, когда семья уже хорошо заработала.
8. Нужно ли раз в месяц прогонять GPT/research пересчет перед ролловером.

## 42. Короткая формула текущей системы

Сигнал:

`VWAP + momentum + trend + breakout + volume + orderbook imbalance`

Вход:

`long по ask`, `short по bid`

Выход:

`candle_like trailing stop`, shadow-сравнение со `stream_stoplimit`

Размер:

`min(ГО-лимит, полный стоп в рублях)`

Защита:

`Risk Governor по profile/family/day`

Главная метрика:

`закрытый net PnL после комиссии`, а не win rate и не грязный плюс.
